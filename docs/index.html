Point it at any repository and get a contributor timeline — a publication-ready SVG for your paper or README, and a self-contained interactive HTML page for digging in. Time across the top, contributors down the side, every bar shaded by how busy each month was.

$cargo install contributor-graphs

Two outputs

One command, two files.

Every run writes both. The SVG is vector, self-contained, and drops straight into a manuscript figure or a README. The HTML carries the same data but lets a reader filter, sort, zoom the timeline, and read each contributor's detail on hover — no server, no build step, just a file you can open or commit to a gh-pages branch.

Static chart repo.svg

Crisp at any size, avatars embedded as data URIs, theme-matched. The top contributors by commit count, ordered however you like. This is the one you cite.

Interactive page repo.html

Search and sort, set a minimum-commit threshold, filter by affiliation, drag the activity strip to zoom a date range, flip to dark mode, export a PNG. State lives in the URL, so a filtered view is shareable.

Install

Get the binary.

You'll need Rust. The GitHub CLI is optional but worth having — it's how the tool finds a token for username and avatar lookups without hitting the anonymous rate limit.

# from crates.io
cargo install contributor-graphs

# or from a local clone
git clone https://github.com/ewels/contributor-graphs
cargo install --path contributor-graphs

In CI, the GITHUB_TOKEN that Actions injects is picked up automatically — nothing else to configure.

Usage

Point it at a repo.

The first argument is a local path, a GitHub owner/repo slug, or a git URL. Remote repositories are cloned (commit history only) into a cache and reused on the next run.

$ contributor-graphs nf-core/rnaseq Clone the history, enrich from GitHub, write nf-core-rnaseq.svg and .html.
$ contributor-graphs . --open Use the current checkout and open the interactive page when it's done.
$ contributor-graphs MultiQC/MultiQC --min-commits 10 --sort commits Trim the long tail of one-off contributors and order by who committed most.
$ contributor-graphs nf-core/rnaseq --by-affiliation Collapse the chart to one row per organisation instead of per person.

Affiliations

Group people by where they work.

The tool reads each contributor's company from their GitHub profile and uses it to colour the chart by organisation. Spelling variants get folded together — seqeralabs, Seqera Labs and Seqera all become one group — and the most common organisations get distinct colours while the long tail shares a neutral grey.

When the organisations are the story rather than the individuals, --by-affiliation merges everyone from each one into a single bar (in the interactive page it's a live toggle — try it in the chart above). The auto-detection is imperfect, so a small tab-separated file overrides it:

# groups.tsv — matcher (name, email, or login) → group
ewels             Seqera
apeltzer          Boehringer Ingelheim
qbicsoftware      QBiC

$ contributor-graphs nf-core/rnaseq --groups groups.tsv

A matching --identities file does the same for people who commit under several names or emails over the years.

Reference

The flags you'll reach for.

The full list is in --help; these are the ones that matter day to day.

FlagWhat it does
-o, --output-dirWhere to write the two files. Defaults to the current directory.
--min-commitsHide contributors below this many commits in the static chart.
--max-contributorsCap the static chart to the top N by commits (default 40).
--by-affiliationOne row per organisation instead of per person.
--sortfirst · last · commits · duration · name
--include-botsKeep bot accounts, which are dropped by default.
--groupsTSV mapping contributors to organisations.
--identitiesTSV merging a person's several names and emails.
--since / --untilRestrict to a window of commit history.
--no-githubSkip all network calls; render from git alone.

How it works

From git log to graph.

  1. Read the history. git log gives every commit's author, email and timestamp, honouring .mailmap.
  2. Merge identities. Commits are clustered by shared email, then by shared name — the usual mess of one person under five addresses, folded back together.
  3. Ask GitHub. Each identity is resolved to a username, avatar and profile in parallel, so a noreply email or an old address still finds the right account.
  4. Bin and draw. Commits are counted per month per person, then rendered to a self-contained SVG and an interactive HTML page with everything embedded.
